# ACE bulk fixture facts

Loading the committed ACE Fe3O4 bulk trajectory through the post shell must
reproduce its documented population, box, periodicity and constant ACE spin
populations. This is the entry point every trajectory analysis depends on.

## Sub-features

- `fixture-frames` loads all 350 frames with first TIMESTEP 100 and last 3587.
- `fixture-population` maps the `element` column to ACE types 1/2/3 with counts 64/128/256 of 448 atoms.
- `fixture-box` reads a cubic 16.79 A box with `pp pp pp` bounds, so PBC is (True, True, True).
- `fixture-spin` keeps n_up = 64, n_down = 128, n_o = 256 in every frame, so the up fraction is exactly 1/3.
- `fixture-composition` checks the type/element/spin convention through the counts: metal:O = (64 + 128):256 = 3:4 and type1:type2 = 1:2.

Type, element label and spin convention (lammpkeeper/common/mapping.py, ACE preset):

| type | dump `element` | label | meaning |
|---|---|---|---|
| 1 | Fe | Fe_up | iron, spin up |
| 2 | Mn | Fe_down | iron, spin down, carried in the ACE potential's Mn slot (not manganese) |
| 3 | O | O | oxygen |

In this fixture type 1 occupies the 64 tetrahedral (A) sites and type 2 the 128
octahedral (B) sites, matching magnetite's 1:2 A:B ratio; that site assignment
is fixture-specific and is documented here, not checked.

## How to get to it (user POV)

- `lkpr post --dump tests/fixtures/ace_examples/regular_MD/traj.dump` then `analyze spin` in the shell.
- `python3 -m lammpkeeper post --dump <fixture> --analyze spin`.
- From Python, `LammpsPostShell().do_load('dump <fixture>')` then `analyze_spin_evolution(state.dump_frames, state.dump_col_idx, dt_fs=state.dt_fs)`.

## Driving it with verify_refs.py

Preconditions:

- `HOME="$LKPR_HOME"` is a disposable directory.
- Doctor reports `fixture: present`.

- **Run the check.** `HOME="$LKPR_HOME" python3 .claude/skills/verify/scripts/verify_refs.py --only fixture-ace-bulk`. Output ends with `PASS fixture-ace-bulk — all 13 reference keys within tolerance (1 analytic, 12 fixture)`.
- **Inspect a key.** Open `results.json` in the evidence directory; `keys.type_counts.measured` is `{"1": 64, "2": 128, "3": 256}` and `keys.pbc.measured` is `[true, true, true]`.
- **Proof.** Quote the `PASS fixture-ace-bulk` line from `summary.txt` and the git SHA from `doctor.txt`.

## Gotchas

- The shell prints a RuntimeWarning that force field, units and dt_fs (0.25 fs) are heuristic guesses from the dump. That is expected for this fixture, which has no input script loaded; it is not a failure.
- `parse_dump` alone returns a list without `reader.boundary`; PBC is only known on the shell's `LazyFrames`. Do not replace the shell load path with a direct parse.
- The spin populations are constant because the dump's `element` labels never change. This check proves label mapping and counting, not spin dynamics.
- `box_lengths` refers to frame 0 (step 100) only, where the bounds are exactly 0..16.79 A. The run is NPT: later frames have box lengths between 16.737 and 17.182 A and a moving origin. Do not read 16.79 as the trajectory's box.
- Both fixture POSCARs (`regular_MD` and `spin_equilibration_MD`, `POSCAR_Fe3O4_FeM.lmp`, "generated by phonopy") assign type 2 the manganese mass 54.938045 because phonopy filled masses from the element symbol. The repository's own writer (`lammps_pre/state.py`, ACE preset) gives type 2 the iron mass 55.845. Position-based analyses are unaffected; dynamics differ by the 0.984 mass ratio.
- `tests/fixtures/**` is read-only; a changed fixture invalidates every reference in this map.
