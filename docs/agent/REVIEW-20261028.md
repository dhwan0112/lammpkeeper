### Highest-priority follow-ups — parent independently reproduced

Priorities are triage judgments, not measured physical-error magnitudes. These
three cases warrant explicit attention before treating the toolkit as generally
validated:

- **P1, F-IO-1 — malformed thermo rows silently disappear.**
  `lammps_post/parsers.py::parse_log` accepts rows `0 300 -10`, `10 301`,
  `20 302 -12` under `Step Temp PotEng` by dropping the short middle row. Parent
  measured steps `[0,20]`, `timeline_valid=True`, zero warnings; the corrupt row
  is not retained in raw blocks. A future regression must require visible
  rejection/diagnosis and source preservation, not normalize the expected loss.
- **P1 scientific-ingestion risk, F-REF-1 — unsupported CIF occupancy is ignored.**
  `lammps_post/references.py::parse_cif` returns a full X atom for a P1 site with
  explicit occupancy zero. Parent reproduced that returned atom. Partial/disordered
  weighting is not implemented; unsupported input should reject visibly rather
  than imply a fully occupied reference. No real material result was measured.
- **P1 data-loss risk, F-PREP-3 — successful copyback can follow destination children.**
  The generated script's `cp -a -- source "$DEST"/` primitive follows an existing
  output-file symlink and overwrites its target. Parent reproduced this only in
  a disposable temporary tree: the symlink remained and its separate target
  changed from old content to new output. This is a primitive-level safety repro,
  not an HPC job run. The exclusive failure archive does not cover this successful
  copyback case. Fixing generated job scripts requires the maintainer's human gate.

### Other parent-reproduced findings

- **P2, F-SESSION-1 — wrong interactive RDF reference pair.**
  `lammps_post/shell.py::_iplot_rdf` parses a hyphenated cache name such as
  `rdf_O-O` by splitting underscores; it falls back to `('Fe','O')`. Parent and
  worker mocked-dispatch reproductions measured that wrong pair passed to the
  reference calculator. Multiple selected curves also share one reference list.
  This is a scientific-display risk, not a measured RDF-kernel error or actual
  material/reference rendering validation. Needs a dedicated regression/fix.
- **P2, F-CLI-1 — empty plain-text table crashes.**
  `lammpkeeper/common/display.py::print_table`, with `HAS_RICH=False`,
  `headers=['A']`, `rows=[]`, raises `TypeError: 'int' object is not iterable`.
  The starred row-width expansion leaves a single scalar argument to `max`.
  Existing ordinary table tests do not cover this empty case.
- **P3, F-CLI-2 — history read is not bounded by the write cap.**
  `lammpkeeper/common/hosted.py::_setup_history` reads an entire inherited file.
  A parent-created 5,000-line isolated history loaded 5,000 entries despite the
  2,000-line write limit. This is a startup/resource limitation; OPS-1's write
  bound does not promise bounded loading. Multiple standalone instances also
  share a global buffer/exit writers; cross-file exit-time contamination remains
  source-inferred, not parent-reproduced.
- **P3, F-SESSION-2 — saved recipe names and redo/edit names disagree.**
  A saved `charge_evolution` recipe followed by `plot redo charge` reports no
  saved `charge` recipe. Parent and worker reproduced the missing-recipe message.
  Other normalized plot names share this source-level risk; no new alias or CLI
  change is implemented here.
- **P3, F-CORE-1 — near-face wrapping is not strictly half-open/idempotent.**
  A unit orthogonal Box, PBC `(True,False,False)`, point `[-1e-17,.25,.5]` wraps
  first to `[1,.25,.5]`, then to `[0,.25,.5]`. Parent reproduced this float64 face
  rounding. Equivalent periodic positions differ in representation; no RDF/MSD
  numerical or physical error was measured. A separate fix must define/test the
  face convention rather than silently alter it in comments.

### Review limitations and source-inferred risks

- **F-CORE-2 — a finite-cube oracle's interior optimum is not a general bound.**
  An independent worker probe with rows `(1,0,0),(9,1,0),(0,0,1)`, delta
  `(0,.6,0)` finds an interior `[-7,7]^3` minimum of squared norm `.36`, but the
  outside image `(-9,1,0)` gives `.16`. This does not show existing test answers
  or production QR MIC are wrong: selected strong-tilt tests use a larger range.
  Comments now avoid treating interiority alone as a proof for future cases.
- **F-VERIFY-1 — second-resolution evidence directories can collide.**
  Concurrent verifier runs with the same root/SHA/mode/second share a `mkdir -p`
  path and may overwrite logs. Source-inferred; no concurrency reproduction.
  Use distinct `LKPR_VERIFY_DIR` roots pending a dedicated fix.
- **F-VERIFY-2 — unchecked `mktemp` failure can weaken isolation.**
  The verifier does not individually validate both temporary directory creation
  results. Source-inferred; unsafe failure paths were not executed against the
  user's environment. A separate failure-injection regression is appropriate.
- Verifier nonempty-file/section gates are smoke evidence, not image decoding,
  numeric export or solver validation. Only logs and the copied analysis summary
  survive cleanup, not disposable images/prep artifacts. Joined emoji/control
  widths are approximations, not a terminal/grapheme emulator. Direct `--find`
  exit-status behavior has not been exhaustively fault-injected.

## Verification method and limits

The baseline checker removes **only genuine leading** module/class/function
Python docstrings, then compares complete ASTs. All other string constants,
assertions, expectations, imports, decorators, defaults and generated payloads
remain included. It also checks Python 3.9 grammar and complete English
module/class/function documentation (manual meaning review plus automated
presence/no-Hangul checks). This is not execution on a Python 3.9 interpreter.

Rust/Shell nonblank non-full-line-comment source is compared exactly; shebangs
are separately preserved. Parsed TOML data must match, and both shell files must
pass `bash -n`. Fixtures, lockfiles and the thesis tag remain unchanged. The
registration audit measured all 34 tracked test modules registered exactly once.
