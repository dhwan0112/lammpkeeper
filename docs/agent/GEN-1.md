Status: implementation, independent review and full verification complete.
Published as [PR #19](https://github.com/dhwan0112/lammpkeeper/pull/19).

## Approved design

The maintainer approved ADR-0002's recommended contract on 2026-10-28. Two
independent read-only architecture reviews found a backlog/ADR source-order
conflict and identified compatibility boundaries before runtime work started.
The backlog now follows ADR-0001/0002. This is not a new force-field convention
or permission to change existing numeric expectations.

`lammpkeeper.core.SpeciesMap` owns explicit label-to-type-set selections. Core
contains no chemical-element/force-field literals, domain aliases, display
translations or file readers. Its defensive immutable snapshots preserve sparse
type IDs and union repeated labels. Exact labels and explicit groups can overlap,
but unknown group references or conflicting exact-label definitions raise.
Unknown species list valid choices rather than falling back to all atoms.

```python
from lammpkeeper.core import SpeciesMap

species = SpeciesMap.from_atom_types(
    {2: 'A', 7: 'A', 9: 'B'}, groups={'X': [2, 9]})
assert species.resolve('A') == frozenset({2, 7})
assert species.resolve('X') == frozenset({2, 9})
```

`common/mapping.py` remains the preset/compatibility adapter. Legacy scalar
helpers, canonical slot tables, conditional group aliases, friendly plot labels,
cache keys and filenames stay compatible. Existing species-selection helpers
route through the generic model instead of retaining separate generic logic.

## Metadata contract

For type labels, fill absent assignments from **input → data Masses comments →
dump → user fallback**, preserving each numeric ID. Contradictory explicit
sources warn with source/type/values and reject application; inferred FF/count
labels cannot veto explicit metadata. Canonical proxy-to-analysis labels remain
an adapter operation with existing eligibility checks, not a generic inference.

- `parse_data_species(path)` extracts exact `# A` / `# species=A` comments.
  Missing comments yield no identity; ambiguous free text warns and is ignored.
  Numeric mass is not a species identifier. `parse_data_file` still returns its
  existing `(atoms, box, masses)` tuple.
- `DumpReader.type_labels` snapshots only numeric type/label evidence from
  consumed frames, including projected reads. `type_ids` separately records raw
  numeric type IDs even without element labels; guessed FF table keys are not
  evidence that those IDs exist. Header indexing does not scan all atom rows.
  A type cannot acquire a contradictory label in a later consumed frame. An
  atom may change its type without changing that convention.
- Element-only reader compatibility remains separate: legacy synthesized numeric
  types are not promoted to authoritative explicit source evidence.
- `SessionState.species_map` is derived from current metadata rather than cached
  forever. Managed source changes validate/invalidate results and automatic
  geometry; a manual surface remains manual. Arbitrary direct mutation of the
  legacy `ff_info` dictionary does not promise automatic invalidation of prior
  numerical results.

The maintainer separately approved preserving `set types` as an explicit,
temporary manual analysis-label override, distinct from automatic user fallback.
It warns when different from raw sources; input/data/dump load or unload expires
it visibly. Manifest/log changes retain it, failed transactions roll back, and
`unload all` clears it. Raw file conflicts are still checked; the command is not
a force flag that reconciles contradictory files.

### Optional manifest

A manifest is explicitly loaded, not auto-discovered or generated by prep:

```json
{
  "schema_version": 1,
  "species_groups": {"X": [2, 9]},
  "domain": "example",
  "provenance": {"note": "Generic labels supplied by the LAMMPS files"}
}
```

`domain`/`system` records are retained metadata, not active recipe/settings
instructions. Top-level fields duplicating LAMMPS type identities, units,
boundary, pair style or timestep are rejected; opaque nested records do not
become authoritative LAMMPS metadata. Optional `provenance.file_hashes` maps
manifest-relative paths to SHA-256 hex digests; explicitly referenced files must
exist and match their bytes. Relative parent paths are supported, not sandboxed.
Duplicate JSON keys, malformed schema/groups and forbidden fields fail visibly.

A well-formed manifest can load first. Missing group references remain pending,
not proof that a type exists; active map construction fails clearly until typed
sources establish all references. Source unload can make groups pending again.
An exact-label conflict is rejected as soon as established memberships prove it;
unknown extra IDs alone remain pending because later sources may establish the
same label. Both load orders follow that rule, without analyzing a partial group.

```text
load input "run.in"
load data "system.data"
load dump "trajectory.dump" --cache-mb 0
load manifest "lkpr-run.json"
analyze msd --species X
analyze rdf A-B
unload manifest
```

These commands assume matching user-provided files with the example type labels;
they do not generate a physical reference or run LAMMPS.
