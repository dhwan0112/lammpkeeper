## Fixed in this PR (each failing first, then passing; measured)

1. **Thermo plots ignored `set dt`.**
   - *Trigger:* the input declares a timestep and the log does not.
   - *Where:* `lammps_post/shell.py`, `_thermo_plot_metadata`.
   - *Before:* MSD/OAR used the manual 0.5 fs but thermo plots used the input's 2 fs. The parent reproduced this as `('metal', 2.0)` with `dt_fs = 0.5`.
   - *Now:* with no log-declared dt, the precedence is manual override, then explicit input, then session dt. A log that declares a dt keeps it.
   - *Test:* `test_session_metadata.test_thermo_plots_honor_a_manual_dt_over_the_input_timestep`. It fails on the pre-fix code and passes after.
2. **`${var}` in `units`, `atom_style` and `pair_style` was stored raw.**
   - *Where:* `lammps_post/parsers.py`, `parse_input`.
   - *Before:* `pair_style ${ff}` was classified as an explicit `generic` family, and `atom_style ${a}` became an explicit field with value `${a}`.
   - *Now:* these lines go through the same `_resolve_string` as `pair_coeff` and `read_data`, so a substitution resolves or raises.
   - *Prep inputs:* prep templates contain no `$` on these lines, so prep-written inputs give unchanged output.
   - *Test:* `test_run_metadata.test_style_declarations_resolve_substitutions_or_raise`. Pre-fix it failed with `unsupported units style '${u}'`.
3. **`lkpr-rs` missed an overflow in the poll in which the backend exited** (`rust/lkpr-rs/src/backend.rs`).
   - *Before:* a backend that wrote 16 MiB + 1 byte and exited was reported as `invalid_backend_output`.
   - *Now:*
     - A check after the loop reports `output_too_large`.
     - The reader also stops storing after the first dropped chunk, so the kept stream has no hole.
   - *Test:* `oversized_output_is_detected_when_the_backend_exits_at_once`. Pre-fix it panicked with `invalid_backend_output`.
4. **`lkpr-rs --json` exited 0 when stdout could not be written** (`main.rs`, `print_raw`).
   - *Now:* it fails with `output_write_failed` and exit 1.
   - *Test:* `json_mode_write_failure_is_not_success`, with stdout set to `/dev/full`. It fails pre-fix.
   - `doctor` now returns 130 after Ctrl-C. This is documented, but no process test covers it.
5. **`/verify-lkpr` full mode dropped `--plot all` without a record when matplotlib was missing.**
   - *Now:* it records `SKIP plots`.
   - The empty-array expansion is also safe under `set -u` on bash < 4.4.
6. **`tests/test_rust_cli.py` assumed `rust/lkpr-rs/target/debug`.**
   - *Now:* it asks cargo (`--message-format=json`) for the executable, so `CARGO_TARGET_DIR` and a configured `build.target-dir` work.
   - Measured: 7 Rust-CLI tests pass with `CARGO_TARGET_DIR=/tmp/opencode/ui1-target`.
